## Apple Developer / EAS üzerinde gereken manuel işlemler

1. Apple Developer Program'a kayıtlı doğru ekiple giriş yapın. Sadece Personal Team kullanılıyorsa push desteği olan Program üyeliği gerekir; mevcut ekibin üyelik durumu bu oturumda doğrulanmadı.
2. Certificates, Identifiers & Profiles → Identifiers altında **com.nakliyego.customer** ve **com.nakliyego.driver** için **Push Notifications** capability'sini etkinleştirin. Gerekli yetki için Account Holder/Admin erişimi kullanın.
3. Uygun APNs authentication key (.p8), Key ID ve Team ID'yi hazırlayın. Gereksiz yere mevcut anahtarları iptal etmeyin. Ekipteki anahtarın uygun topic/bundle kapsamını iki uygulama için doğrulayın.
4. Her uygulama klasöründe `eas credentials -p ios` → `development` → `Push Notifications: Manage your Apple Push Notifications Key` ile doğru anahtarı ilgili projeye bağlayın. `.p8` ve EAS erişim token'larını repoya veya mobil public env'e koymayın.
5. Push capability'sini içeren provisioning profillerini yenileyin ve iPhone 13 UDID'sinin development/ad hoc profilinde kayıtlı olduğunu doğrulayın. APNs yetkisi olmayan eski profili kullanmayın.
6. İki native development build alın ve iPhone'a yükleyin:

```sh
cd /Volumes/KIOXIA/nakliye-app/frontend/customer-app
eas build --platform ios --profile development
```

```sh
cd /Volumes/KIOXIA/nakliye-app/frontend/driver-app
eas build --platform ios --profile development
```

Bunlar App Store/production gönderimi yapmaz. Lokal alternatif, aynı imzalama koşulları sağlandıktan sonra `npm run ios -- --device` kullanmaktır. Mevcut native/Pods onarımları korundu; `prebuild --clean` çalıştırılmadı. Development profili beta adresini taşır. Dağıtım profillerinde APS environment imzalama/provisioning ile uyumlu olmalıdır; development entitlement'ını production imzasına zorlamayın.

7. Geliştirme uygulamalarında bildirim izni verip beta test hesaplarıyla giriş yapın. İki uygulama ayrı Expo token üretmeli; `/api/push/token` kaydı doğru projectId ile başarılı olmalıdır. Kullanıcı izin verdiyse bile token kaydı başarısız olabilir; cihaz ayarındaki izin göstergesi APNs/EAS kurulumunun tamamlandığına kanıt değildir.
8. Expo projesinde enhanced push security açıksa backend ortamına `EXPO_ACCESS_TOKEN` koyun; frontend'e eklemeyin. Bu anahtar burada oluşturulmadı veya değişmedi.

Kaynaklar: [Expo kurulum](https://docs.expo.dev/push-notifications/push-notifications-setup/), [Expo gönderim ve receipts](https://docs.expo.dev/push-notifications/sending-notifications/), [Apple desteklenen iOS yetenekleri](https://developer.apple.com/help/account/reference/supported-capabilities-ios).

## Uygulama ve backend davranışı

- iOS alert/sound/badge izinleri açık istenir; provisional/ephemeral izinler token alımını engellemez. ProjectId yoksa sessizce yanlış projeden token alınmaz.
- Uygulama aktif olduğunda ve APNs token rotation olduğunda kayıt yenilenir. Explicit izin ekranı da aynı kayıt yöneticisini kullanır. Logout önce yeni kayıtları durdurur, devam eden kaydı bekler ve sonra token bağlantısını kaldırır. İzin kapatılması bilinen token'ı kaybettirmez. Kayıt POST yanıtı kaybolsa bile token önceden saklanır ve logout temizliği yapabilir.
- Ön planda banner/list/sound handler'ı korunur. Bildirimden yalnız `load`/`conversation` yönlendirilir; aynı cold-start/live response bir kez işlenir. Ödeme push'una dokunmak onay vermez: iş detayı `loads.get` ile backend'den yüklenir; eski payload tutarı/durumu güvenilir kabul edilmez.
- Ödeme onayı isteği şoföre; kabul ve ret müşteriye gider. Teklif, mesaj, yakındaki iş, nakliye durumları ve çıkışta token silme korunur. Olay bazında kullanıcı başına Redis `SET NX` tekrarlı gönderimi engeller. Mesaj idempotency'si korunur.
- Expo'ya en fazla 100 mesajlık, aynı EAS projesine ait gruplar gönderilir. ProjectId'siz eski kayıtlar karışık proje hatasını önlemek için tek tek gönderilir.
- Ticket sayısı, status/id ve HTTP/top-level hataları kontrol edilir. Ticket veya receipt `DeviceNotRegistered` ise yalnız gönderim anındaki aynı kullanıcı/kayıt sürümü temizlenir; sonradan başka hesaba aktarılmış/yeniden kaydedilmiş token silinmez. `InvalidCredentials` gibi kurulum hatalarında token korunup hata loglanır.
- Başarılı ticket kimlikleri Redis'te saklanır. Receipt worker ilk kontrolü gönderimden 15 dakika sonra yapar; her dakika due kayıtları en fazla 1000'lik grupta kontrol eder. Eksik/geçici başarısız receipts 15 dakika sonra tekrar kontrol edilir; 24 saati geçenler raporlanıp kapatılır. Worker ana backend process'inde başlar; restart bekleyen receipts'i kaybettirmez.
- Push hatası yalnız loglanır; nakliye/karar commit'i geri alınmaz, otomatik şoför onayı oluşturulmaz. Sunucu olay claim'i gönderimden önce alınır: belirsiz ağ sonucunda bildirim yeniden gönderilmez, böylece tekrar riski azaltılır. Push, kalıcı iş durumunun veya uygulamadaki yenilemenin yerine geçmez; sağlayıcının cihazda kesin tek teslimatı garanti edilmez.

## Fiziksel iPhone 13 kabul planı

İki ayrı **beta test hesabı** kullanın: onaylı kurumsal müşteri (en az 500 TL kredi ve politikaya uygun limit), şoför (en az 410 TL kullanılabilir komisyon bakiyesi). Profilde Push izinlerini açın; Focus/Do Not Disturb ve Scheduled Summary'yi test süresince kapatın. Bu ayarlar sessiz teslimata neden olabilir. Token/profil/APNs kurulumu tamamlanmadan test başlamamalı.

Test olaylarını üretmek için `scripts/testing/beta-push-smoke.py` hazırlandı. Yalnız sabit beta adresine gider; sadece `BETA PUSH TEST` başlıklı kendi nakliyelerini değiştirir. Erişim token'larını repo dışında, erişimi kısıtlı iki dosyada tutun. Test scripti token yazdırmaz. Test hesaplarında ayrılmış kredi/komisyon, sonunda `cancel` ile serbest bırakılır.

```sh
python3 scripts/testing/beta-push-smoke.py create --customer-token-file /tmp/customer-beta-token --driver-token-file /tmp/driver-beta-token
python3 scripts/testing/beta-push-smoke.py accept --repeat --customer-token-file /tmp/customer-beta-token --driver-token-file /tmp/driver-beta-token
python3 scripts/testing/beta-push-smoke.py message --repeat --customer-token-file /tmp/customer-beta-token --driver-token-file /tmp/driver-beta-token
python3 scripts/testing/beta-push-smoke.py start --customer-token-file /tmp/customer-beta-token --driver-token-file /tmp/driver-beta-token
python3 scripts/testing/beta-push-smoke.py cancel --customer-token-file /tmp/customer-beta-token --driver-token-file /tmp/driver-beta-token
```

Ret için yeni bir `--state /tmp/another-push-state.json` kullanın; `create`, `reject --repeat`, `cancel` çalıştırın. 0 TL kredi için `create --credit-cents 0` kullanın. Script henüz gerçek telefon token'larıyla çalıştırılmadı; CLI/parse kontrolü yapıldı.
